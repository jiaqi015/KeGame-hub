# Impeccable Design Context

Last updated: 2026-04-21

## Product

This is a unified business workspace with three surfaces:

- `多模型PK`: model comparison and answer synthesis.
- `开放日选址`: professional data-driven site-selection and scenario analysis.
- `我是王牌资产顾问`: a real-estate advisor strategy game about managing listings, owners, customers, market signals, matters, deals, and results.

The next 4-hour sprint focuses on `我是王牌资产顾问`.

## Target Audience

Primary users are business operators, product designers, and internal stakeholders evaluating a real-estate advisor simulation. They are not playing a casual toy; they are judging whether the workspace feels like a credible business game.

For the selling-houses game, the player is a broker / asset advisor handling multiple listings under time, energy, budget, owner, customer, and competition pressure.

## Core Use Cases

- Start a standard or random run.
- Read the daily operating situation quickly.
- Decide which listing, owner, customer, or matter needs attention first.
- Push opportunities forward through believable business actions.
- Understand market, competition, and organization pressure.
- Review what happened and why.
- See run results, personal progress, and leaderboard entry points.

## Brand Personality

The selling-houses UI should feel like a dense, credible operating desk:

- business-real
- sharp and decision-oriented
- compact but not cramped
- concrete and non-jargony
- serious enough for strategy, warm enough to keep playing

It should not feel like:

- a training system
- a CRM admin page
- a generic SaaS dashboard
- a purple/blue AI template
- a card grid with decorative metrics

## Visual Direction

Use a dark, high-density workspace as the base. It should feel like a serious brokerage operating desk, not a consumer dashboard:

- tight information rhythm
- strong hierarchy between today / object / action / evidence
- restrained surfaces with selective emphasis
- status chips, compact tables, timelines, and split panes
- subtle motion only where it explains state changes
- black-green visual core with a single signal green, muted risk red, and very limited cyan
- no white main pages and no black-white mixed shell
- typography should be smaller, tighter, and more editorial than generic SaaS

The main workspace can be compact. Overlays, result views, and detail pages should remain breathable and readable.

## Information Architecture Constraints

The in-run navigation should follow:

```text
经营概览 / 房源 / 客户 / 市场 / 复盘 / 结果 / 我
```

The core workspace structure is:

```text
顶部状态条
左侧一级导航
中间主工作区
右侧洞察与行动侧栏
底部或抽屉流水日志
```

The main priority is always:

1. What am I managing now?
2. What changed?
3. What should I do next?
4. What evidence explains it?

## UX Writing Rules

- Use business language, not abstract model language.
- Say who, where, when, what changed, and what it affects.
- Avoid "教学", "训练营", "刷题", "AI", "智能建议", "工作台", "工作面" as player-facing tone.
- Avoid front-path jargon such as "主矛盾", "锚点", "盘面", "画像", "收口".
- Prefer direct wording such as "业主沟通", "客户承接", "价格", "外部变化", "成交线索", "竞品压力".
- If an action cue appears, it should read like a factual next handle, not a coaching slogan.

## Implementation Rules

- Keep the existing project style unless a file is already being redesigned.
- Do not introduce broad visual rewrites across unrelated workspaces.
- Avoid generic AI design tells: no gradient text, no decorative side-stripe cards, no empty icon grids.
- Preserve mobile usability, but optimize the selling-houses main workspace for desktop first.
- For this sprint, prefer UI projections from existing data over new domain rewrites.
