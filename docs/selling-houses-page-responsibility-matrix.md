# 卖房（资产顾问）页面职责矩阵

最后更新：2026-04-21

这份文档只回答一件事：

> 每个页面到底负责什么，不负责什么。

当前状态：页面职责主线已经收进 [selling-houses-information-architecture.md](/Users/jiaqi/Documents/开放日测算/docs/selling-houses-information-architecture.md)。这份文档继续作为短版检查表，不再单独充当信息架构主文。

本轮补充：跨页经营主语统一由 `workspaceShellProjection.sidebar` 承接，页面主区不再各自重算“今日重点”。

页面一旦职责不清，就一定会出现重复信息、平铺卡片、用户看不出重点的问题。

---

## 1. 一级页面职责

### 1.1 经营概览

负责：

- triage：把用户带去房源、客户、市场或复盘
- 告诉用户今天先进入哪个页面处理
- 抬出当前最值得进入的业务入口
- 用短摘要提示今天外部有没有变化
- 带出昨天遗留是否影响今天

不负责：

- 完整市场拆解
- 长篇证据解释
- 完整房源决策
- 单房执行清单
- 关系池推进明细

### 1.2 房源

负责：

- 单套房怎么判断、怎么执行
- 主矛盾在哪
- 业主、客户、价格、竞品分别卡在哪
- 当前能做什么动作
- 这套房的执行清单和受阻动作

不负责：

- 全局今日排程
- 全市场总览
- 客户池全局排序
- 关系池经营总览

### 1.3 客户

负责：

- 关系推进池
- 已接上的客户关系怎么往后推
- 哪些客户接近报价或谈判
- 哪些客户快流失
- 潜在人群只作为“未接上”的规模信号

不负责：

- 代替房源页做单房决策
- 代替市场页解释商圈信号
- 展开房源主矛盾和执行清单

### 1.4 市场

负责：

- 外因解释
- 外部先变了哪一层
- 变化强度和证据
- 外部变化压到了哪些房源
- 从市场回到房源

不负责：

- 今日工作台
- 今天先处理哪件事
- 完整昨日复盘

### 1.5 复盘

负责：

- 发生了什么
- 为什么会这样
- 哪些动作改变了结果

不负责：

- 今日分诊
- 单房执行
- 市场外因实时解释

### 1.6 结果

负责：

- 这局最后打成什么样
- 哪些房源成交 / 丢盘
- 哪些能力分数高低
- 正式结算和过程台账边界

不负责：

- 今日经营动作
- 复盘因果展开

### 1.7 我

负责：

- 玩家自身状态
- 生涯表现
- 长期沉淀

不负责：

- 今日分诊
- 单房执行

## 2. 壳层与页面主语

### 2.1 壳层唯一跨页主语

`workspaceShellProjection.sidebar` 承接跨页面统一骨架：

- `focus`
- `matter`
- `actionCues`
- `riskCues`
- `marketCues`
- `journal`

这些信息只能在壳层右 rail 做跨页一级表达。页面主区可以引用对应对象，但不能重新组织一套“今日重点”。

### 2.2 页面主区 canonical projection

- overview：`buildDashboardProjection`
- cases：`buildCaseDetailProjection`
- customers：`buildOpportunityListProjection`
- market：`buildMarketProjection`
- review：`buildReviewProjection`
- results：`buildResultProjection`

页面主区只消费自己的 canonical projection。需要跨页判断时，先进入 shell projection，而不是在页面里临时重算。

## 3. 两组重点边界

### 首页 vs 市场页

首页回答：

- 今天该进入哪里处理
- 当前哪个业务入口最要紧
- 今天有没有外部变化摘要

市场页回答：

- 外部哪里先变
- 变化怎么传下来
- 哪套房先被压到

一句话边界：

- 首页负责“排顺序”
- 市场页负责“讲外因”

### 房源页 vs 客户页

房源页回答：

- 这套房现在卡在哪
- 这套房该先做哪一步
- 哪些动作能做，哪些动作受阻

客户页回答：

- 哪些关系已经接上
- 哪些关系临近成交
- 哪些关系在掉线
- 哪些潜在人群还只是未接上信号

一句话边界：

- 房源页负责“单房决策与执行”
- 客户页负责“关系推进池”

## 4. 去重规则

同一类信息只允许一个页面做一级表达。

### 4.1 今日优先事项

- 一级表达：壳层右 rail + 首页 triage
- 其他页面：不重复做“先处理哪件事”

### 4.2 外部变化总览

- 一级表达：壳层右 rail + 首页摘要
- 深入表达：市场页

### 4.3 受影响房源

- 一级表达：市场页
- 首页只允许在当前主房源里提示“今天被外部命中”

### 4.4 单房决策事实链

- 一级表达：房源页
- 首页只允许放短版事实链

### 4.5 关系推进池

- 一级表达：客户页
- 房源页只允许展示当前房源相关客户，不展示全局客户池

## 5. 信息优先级规则

### 首页

1. 分诊入口
2. 当前最需要进入的页面
3. 今天市场变化摘要
4. 昨日遗留

### 市场页

1. 今天先变的层
2. 当前层证据
3. 受影响房源

### 房源页

1. 当前主矛盾
2. 事实链
3. 可做动作
4. 最近变化

### 客户页

1. 已接上的关系
2. 临近成交和掉线风险
3. 潜在人群规模信号

### 复盘 / 结果 / 我

1. 沿用壳层 dark/green 视觉语法
2. 不先改业务结构
3. 不引入独立白底页面

## 6. 首屏承载规则

所有页面统一执行：

- 首屏只保留一级信息。
- 二级信息优先放页内 tab、折叠区、drawer、二级页。
- 不允许把摘要、证据、明细、动作都挂成同级首屏模块。

### 经营概览

- 首屏只留：
  - 分诊入口
  - 今日事项
  - 当前主房源
- 周节奏明细、边界说明进入次级承载。

### 房源

- 首屏只留：
  - 当前对象
  - 当前问题
  - 诊断摘要
  - 可做动作
- 对象状态、客户细节、最近变化、判断依据进入页内 tab。

### 客户

- 首屏默认只留一类关系池。
- 临近成交、掉线风险、潜在人群通过页内 tab 切换，不再同屏平铺四块主内容。

### 复盘

- 首屏只留回看结论和主变化。
- 昨日摘要、客户线、周沉淀进入页内 tab。

### 流水 / 日志

- 首屏只留范围切换和流水本身。
- 说明型指标和教学文案不占主舞台。

---

## 6. 判断标准

每次加模块前先问：

1. 这个模块是在帮用户排顺序、讲因果、做决策，还是看结果？
2. 它是不是已经在别的页面承担过了？
3. 如果拿掉它，这个页面的主线会不会更清楚？
4. 它是一级信息还是二级信息？

如果回答不清，就不要先加块。
