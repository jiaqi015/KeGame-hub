# 卖房（资产顾问）页面职责矩阵

最后更新：2026-04-21

这份文档只回答一件事：

> 每个页面到底负责什么，不负责什么。

当前状态：页面职责主线已经收进 [selling-houses-information-architecture.md](/Users/jiaqi/Documents/开放日测算/docs/selling-houses-information-architecture.md)。这份文档继续作为短版检查表，不再单独充当信息架构主文。

页面一旦职责不清，就一定会出现重复信息、平铺卡片、用户看不出重点的问题。

---

## 1. 一级页面职责

### 1.1 经营概览

负责：

- 排今天顺序
- 告诉用户今天先处理哪几件事
- 抬出当前主房源
- 提醒今天外部有没有变化
- 带出昨天遗留是否影响今天

不负责：

- 完整市场拆解
- 长篇证据解释
- 完整房源决策

### 1.2 房源

负责：

- 单套房怎么打
- 主矛盾在哪
- 业主、客户、价格、竞品分别卡在哪
- 当前能做什么动作

不负责：

- 全局今日排程
- 全市场总览

### 1.3 客户

负责：

- 哪些客户值得推
- 哪些客户快流失
- 客户当前阶段和推进阻力

不负责：

- 代替房源页做单房决策

### 1.4 市场

负责：

- 外部先变了哪一层
- 变化强度和证据
- 外部变化压到了哪些房源
- 从市场回到房源

不负责：

- 今日工作台
- 今天先处理哪件事
- 完整昨日复盘

### 1.5 复盘

负责：

- 发生了什么
- 为什么会这样
- 哪些动作改变了结果

### 1.6 结果

负责：

- 这局最后打成什么样
- 哪些房源成交 / 丢盘
- 哪些能力分数高低

### 1.7 我

负责：

- 玩家自身状态
- 生涯表现
- 长期沉淀

## 2. 两个重点页面的边界

### 首页 vs 市场页

首页回答：

- 今天先做什么
- 当前主房源是谁
- 今天有没有外部变化

市场页回答：

- 外部哪里先变
- 变化怎么传下来
- 哪套房先被压到

一句话边界：

- 首页负责“排顺序”
- 市场页负责“讲外因”

---

## 3. 去重规则

同一类信息只允许一个页面做一级表达。

### 3.1 今日优先事项

- 一级表达：首页
- 其他页面：不重复做“先处理哪件事”

### 3.2 外部变化总览

- 一级表达：首页只放摘要
- 深入表达：市场页

### 3.3 受影响房源

- 一级表达：市场页
- 首页只允许在当前主房源里提示“今天被外部命中”

### 3.4 单房决策事实链

- 一级表达：房源页
- 首页只允许放短版事实链

---

## 4. 信息优先级规则

### 首页

1. 今日事项
2. 当前主房源
3. 今天市场变化
4. 昨日遗留

### 市场页

1. 今天先变的层
2. 当前层证据
3. 受影响房源

### 房源页

1. 当前主矛盾
2. 事实链
3. 可做动作
4. 最近变化

---

## 5. 判断标准

每次加模块前先问：

1. 这个模块是在帮用户排顺序、讲因果、做决策，还是看结果？
2. 它是不是已经在别的页面承担过了？
3. 如果拿掉它，这个页面的主线会不会更清楚？
4. 它是一级信息还是二级信息？

如果回答不清，就不要先加块。
