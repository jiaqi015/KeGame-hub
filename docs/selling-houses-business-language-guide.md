# 卖房（资产顾问）业务语言指南

最后更新：2026-04-19

这份文档只管一件事：

> 全局设计、页面文案、事件描述、系统建议，怎么写得像真实业务，而不是像 AI 总结。

底层可以有模型、概率、状态、Projection。

但玩家看到的内容，必须像一个真实资产顾问每天面对的局面。

---

## 0. 一句话原则

少说抽象判断，多说业务事实。

所有文案都尽量回答：

```text
谁
在什么时间
在哪个地方 / 哪套房 / 哪个客户 / 哪个业主
因为哪个事实
做了什么动作
导致什么变化
下一步应该怎么做
```

如果一句话里没有事实、对象、动作、影响，通常就是 AI 味。

---

## 1. 为什么会有 AI 味

AI 味通常来自五种问题。

### 1.1 只说结论，不说事实

不好：

```text
客户意向提升。
```

好：

```text
李女士第二次看 A 房时带了家人，并主动问了付款周期。她已经从普通看房进入认真比较。
```

### 1.2 只说模型，不说现场

不好：

```text
该房源竞争压力较大。
```

好：

```text
同小区这周新上了 3 套两房，其中 2 套单价比 A 房低 3%-5%。客户会先拿它们和 A 房比较。
```

### 1.3 只说状态，不说变化原因

不好：

```text
业主信任上升。
```

好：

```text
王先生今天第一次主动问同小区成交价，也同意周末开放日。说明他开始接受你对市场的判断。
```

### 1.4 只说建议，不说为什么

不好：

```text
建议优化营销策略。
```

好：

```text
A 房这周曝光不少，但咨询少，说明卖点没有打中客户。建议先重写主图文案，把“满五唯一、楼层好、业主配合看房”放到前面。
```

### 1.5 用互联网黑话替代业务话

不好：

```text
通过多维度洞察提升客户转化效率。
```

好：

```text
先找出客户卡在哪：没看上房、觉得贵、家人不同意，还是被竞品吸走。不同原因，对应的下一步完全不一样。
```

---

## 2. 四类语言要分开

系统里至少有四类语言，不能混。

### 2.1 架构文档语言

给研发和设计看。

可以出现：

- `World`
- `Case`
- `CustomerCaseRelation`
- `Matter`
- `Event`
- `Projection`
- `readiness`
- `probability`

但也要配业务解释。

推荐写法：

```text
机会不是客户自己，也不是房子自己，而是客户和某套房之间的关系，也就是 `CustomerCaseRelation`。
```

不推荐写法：

```text
机会是一种多主体关系状态聚合。
```

### 2.2 页面标题语言

给玩家扫一眼判断。

要短、像业务入口。

推荐：

- 今日经营
- 房源
- 客户
- 市场雷达
- 昨日情报
- 排行榜
- 复盘

不推荐：

- 综合洞察中心
- 经营效能看板
- 多维协同工作台
- 智能决策面板

### 2.3 事件日志语言

给玩家回看“发生了什么”。

必须写成事实，不写成评价。

推荐：

```text
4 月 19 日下午，李女士参加了 A 房开放日，重点问了车位、付款周期和同小区成交价。
```

不推荐：

```text
客户完成高质量触达，意向增强。
```

### 2.4 系统建议语言

给玩家决定“下一步做什么”。

必须明确动作。

推荐：

```text
建议 2 天内约李女士复看，并准备同小区 3 套竞品对比。
```

不推荐：

```text
建议持续跟进，提升转化。
```

---

## 3. 事件描述标准模板

事件不是一句日志。

事件应该能支持回放、复盘、归因和页面解释。

### 3.1 基础模板

```text
{日期 / 时间}，{主体} 因为 {事实背景}，对 {对象} 做了 {动作}。
结果是 {直接结果}。
影响是 {对客户 / 业主 / 房源 / 市场 / 机会的变化}。
下一步建议 {明确动作}。
```

### 3.2 最短可用版本

```text
李女士参加 A 房开放日后，主动询问付款周期和同小区成交价。她已进入认真比较，建议 2 天内约复看。
```

### 3.3 完整版本

```text
4 月 19 日下午，李女士参加 A 房开放日。她重点问了车位、付款周期和同小区成交价，并主动要求看另一套低价竞品。
系统判断她已经从普通看房进入认真比较。
A 房机会从“预约看房”推进到“看房后”，但竞品拉走风险上升。
下一步建议 2 天内约她复看，并准备 A 房和竞品的价格、楼层、税费对比。
```

### 3.4 事件描述必须包含的东西

至少包含三类：

- 业务事实
- 影响对象
- 下一步动作

如果只有“状态提升 / 风险增加 / 建议关注”，就不合格。

## 4. 页面文案标准

页面文案要帮助玩家判断局面。

不要让玩家读模型报告。

### 4.1 今日经营

今日经营回答：

> 今天先处理什么。

推荐：

```text
今天最该处理 A 房。客户池够，但价格卡住了。王先生已经连续两周拒绝降价，建议先用本周 4 次带看反馈做一次价格沟通。
```

不推荐：

```text
当前经营重点为价格策略优化和客户转化提升。
```

### 4.2 房源页

房源页回答：

> 这套房怎么打。

推荐：

```text
A 房不是没人看，是看完没人愿意往后走。主要卡在价格和竞品比较。建议先把 B 房、C 房成交和客户反馈整理给业主。
```

不推荐：

```text
该房源客户转化链路存在阻塞。
```

### 4.3 客户页

客户页回答：

> 哪些已见面机会值得推进。

推荐：

```text
李女士已经看过 A 房两次，第二次带了家人。她还在比较 B 房，但 A 房楼层和税费更占优。下一步适合约她和家人一起复看。
```

不推荐：

```text
该客户具备较高推进价值。
```

### 4.4 市场雷达

市场雷达回答：

> 外面发生了什么，会影响哪类房和哪类人。

推荐：

```text
本周前滩两房上新增加，低总价房源开始抢客户。预算 650-750 万的客户会更容易比较，A 房需要尽快讲清楚楼层和税费优势。
```

不推荐：

```text
市场供需结构发生变化，建议关注竞品动态。
```

### 4.5 复盘页

复盘页回答：

> 这局为什么赢 / 为什么输。

推荐：

```text
这局没有输在客户少，而是输在看房后的承接。3 个客户看完后都进入比较，但你没有及时做竞品对比，最后其中 2 个被同小区低价房吸走。
```

不推荐：

```text
本局客户转化效率不足，后续需加强精细化运营。
```

## 5. 系统建议标准

系统建议必须像一个懂业务的旁白。

它不替玩家做决定，但要把理由说清楚。

### 5.1 建议模板

```text
建议做 {动作}。
原因是 {事实}。
如果成功，可能带来 {影响}。
如果不做，风险是 {风险}。
```

### 5.2 业主建议

```text
建议今天给王先生做一次价格反馈。
原因是本周 4 组客户都提到“同小区有更便宜的两房”，而王先生已经开始主动问成交价。
如果沟通顺利，价格松动度会提高，后续更容易推进出价。
如果继续拖，A 房会被低价竞品抢走后段客户。
```

### 5.3 客户建议

```text
建议 2 天内约李女士复看。
原因是她第二次看房带了家人，并主动问付款周期。
如果复看成功，这条机会有机会推进到见面前。
如果不跟，B 房经纪人可能会抢先做竞品对比。
```

### 5.4 房源建议

```text
建议先重做 A 房卖点，而不是马上加推广。
原因是曝光已经够，但咨询少，说明客户没有被第一眼打动。
先把“满五唯一、楼层好、业主配合看房”放到主图和标题里，再观察 2 天咨询变化。
```

### 5.5 市场建议

```text
建议本周重点盯前滩两房竞品。
原因是同价位新上房源变多，客户比较会更频繁。
如果竞品继续降价，A 房需要提前准备价格反馈，不要等客户流失后再谈。
```

## 6. 业务化词库

### 6.1 推荐多用的词

- 看房
- 复看
- 面访
- 出价
- 底价
- 付款周期
- 税费
- 竞品
- 同小区
- 同户型
- 同总价段
- 带看反馈
- 成交案例
- 业主预期
- 客户比较
- 家人意见
- 看房后承接
- 价格反馈
- 周末开放日
- 商圈热度
- 新上房源
- 低价盘
- 后段客户
- 丢盘
- 被截胡

### 6.2 慎用或少用的词

这些词不是完全不能用，但不要出现在玩家页面和事件描述里。

- 赋能
- 闭环
- 沉淀
- 链路
- 多维度
- 智能化
- 精细化
- 洞察
- 触达
- 转化效率
- 能力建设
- 全局协同
- 动态优化
- 策略升级
- 运营提效

### 6.3 常见替换

| AI 味表达 | 业务表达 |
| ---- | ---- |
| 客户池偏薄 | 这套房吸引到的人不够多 |
| 转化效率低 | 看房后没人愿意复看 / 出价 |
| 竞品压力大 | 同小区更便宜的房正在抢客户 |
| 业主意愿不足 | 业主还不相信现在价格卖不动 |
| 推进受阻 | 客户卡在价格、家人意见或竞品比较上 |
| 优化营销策略 | 先把卖点讲清楚 / 换主图 / 做竞品对比 |
| 强化客户跟进 | 2 天内约复看 / 补发成交案例 / 问清楚家人意见 |
| 提升业主信任 | 用真实带看反馈和成交数据沟通 |
| 市场发生波动 | 同小区上新变多 / 低价盘成交 / 周末到访下降 |

## 7. 标准事件话术库

### 7.1 客户事件

#### 线上咨询

```text
张先生在线咨询了 A 房，重点问了楼层和税费。他的预算和 A 房匹配，但还没有看房动作，暂时只算轻意向。
```

#### 预约看房

```text
李女士约了周六下午看 A 房。她已经看过同小区两套房，这次更可能是在做横向比较。
```

#### 首次看房

```text
李女士完成 A 房首次看房。她对楼层和采光反馈不错，但认为挂牌价比心理预期高。机会进入看房后阶段，下一步需要做竞品对比。
```

#### 开放日到访

```text
周末开放日带来 6 组到访，其中 2 组停留时间超过 20 分钟。A 房热度上升，但还需要后续承接，否则只会停在看房热闹。
```

#### 再次看房

```text
李女士第二次看 A 房，这次带了家人。她开始问付款周期和业主底价，说明已经进入认真比较。
```

#### 出价

```text
李女士给出 710 万口头出价，低于业主心理价 25 万。现在关键不在客户意向，而在业主是否愿意进入谈判。
```

#### 流失

```text
张先生最终选择了同小区 B 房。原因是 B 房总价低 30 万，且对方经纪人提前做了税费测算。A 房损失一条后段机会。
```

### 7.2 业主事件

#### 周度反馈

```text
今天给王先生做了周度反馈，重点讲了曝光、带看、客户反馈和同小区成交。王先生还没有同意降价，但开始问最近成交价。
```

#### 价格沟通

```text
你用 4 组带看反馈和 2 套竞品成交价跟王先生沟通价格。王先生接受“当前价格偏高”的判断，但还想再等一个周末。
```

#### 同意开放日

```text
王先生同意参加周末开放日，但要求提前确认到访客户质量。业主配合度上升，A 房有机会获得更多看房反馈。
```

#### 拒绝降价

```text
王先生再次拒绝降价，理由是“不着急卖”。价格沟通暂时卡住，后续需要用真实客户流失案例继续沟通。
```

### 7.3 房源事件

#### 曝光上升

```text
A 房更换主图后，曝光明显上升，但咨询没有同步增加。说明客户看到了房源，但卖点还没有打中。
```

#### 客户池变厚

```text
A 房本周新增潜在人群 18 人，其中高匹配 5 人。主要来自预算 650-750 万、想买两房的客户。
```

#### 客户池变薄

```text
A 房潜力池下降，主要因为同小区两套低价房上线。预算相近的客户开始优先比较竞品。
```

#### 后段机会增加

```text
A 房新增 1 条后段机会。李女士复看后开始问付款节奏，下一步可以推动双方见面。
```

### 7.4 市场事件

#### 同小区上新

```text
同小区新上 2 套两房，挂牌价都低于 A 房。接下来一周，客户会更频繁比较价格和楼层。
```

#### 竞品成交

```text
同小区 B 房成交，成交价比 A 房挂牌价低 4%。这是一次适合拿给业主看的价格信号。
```

#### 周末热度变化

```text
本周末前滩两房到访增加，但客户更集中看低总价房。A 房如果价格不动，需要把楼层和税费优势讲得更清楚。
```

### 7.5 组织和竞争事件

#### 同 ACN 联卖

```text
同 ACN 经纪人带客户看了 A 房。客户对房子有兴趣，但客户关系不在你手上。房源获得机会，同时也增加被别人成交的可能。
```

#### 跨品牌截胡

```text
另一品牌经纪人提前带客户看了 B 房，并做了税费测算。李女士对 A 房的注意力下降，A 房机会被竞品拉走。
```

#### 丢盘

```text
A 房最终被同品牌其他门店成交。品牌内成交保住了 ACN 合作，但你失去了这套房的主控成果。
```

## 8. 投影文案规则

Projection 是解释层，不是世界真相。

投影文案可以总结，但必须能追溯到事件。

### 8.1 投影不能凭空说

不好：

```text
A 房当前风险较高。
```

好：

```text
A 房风险升高。过去 7 天有 4 组客户看完后都去比较低价竞品，且业主仍拒绝降价。
```

### 8.2 投影要给业务归因

推荐结构：

```text
判断：A 房客户池不薄，但后段承接不足。
证据：本周 6 组看房，只有 1 组愿意复看。
原因：客户普遍认为价格高，且同小区有两套低价竞品。
建议：先做竞品对比，再和业主谈心理价。
```

### 8.3 投影要避免“神谕感”

系统不要像上帝一样直接宣布结论。

要像一个懂业务的副手，把证据摆出来。

不好：

```text
系统判断该机会有 72% 概率推进。
```

好：

```text
这条机会值得推进。李女士已经复看，家人也到场，但她还在比较 B 房。只要这两天把税费和楼层优势讲清楚，有机会推进到见面。
```

## 9. 数字怎么写才真实

数字不能只作为模型分。

数字要变成业务判断。

### 9.1 分数要解释成业务话

不好：

```text
好房分 76，客户匹配度 82。
```

好：

```text
A 房底子不错，楼层和税费都占优，但挂牌价比同小区近期成交高。客户会愿意看，但看完容易拿竞品压价。
```

### 9.2 概率尽量不直接裸露

玩家不需要每天看一堆百分比。

可以在内部算概率，但页面优先写：

- 很有机会推进
- 值得追
- 需要先补材料
- 暂时别硬推
- 快流失

如果必须露出概率，要配原因：

```text
推进机会较高。客户已复看，预算匹配，家人也参与决策；主要风险是同小区低价竞品。
```

### 9.3 体量数字要有参照

不好：

```text
潜在人群 160。
```

好：

```text
A 房预估潜在人群 160 人，高匹配 28 人。这个池子不薄，问题不在没人看，而在看完后能不能往后推。
```

## 10. 生成文案时的检查清单

每条页面提示、事件日志、系统建议生成后，都要过这 10 个问题。

1. 有没有真实对象：客户、业主、房源、商圈、竞品、经纪人？
2. 有没有具体事实：看房、复看、出价、反馈、成交、上新、降价？
3. 有没有时间：今天、昨日、本周、周末、月底？
4. 有没有地点或范围：小区、商圈、同总价段、同户型？
5. 有没有说明原因，而不是只给结论？
6. 有没有说明影响对象？
7. 有没有明确下一步动作？
8. 有没有少用“赋能、洞察、闭环、转化效率”这类词？
9. 有没有把模型分翻译成业务话？
10. 有没有让玩家读完就知道该先做什么？

少于 6 条通过，就不要上线。

## 11. 和底层架构的关系

业务语言不是单独的文案包装。

它要吃底层事实。

### 11.1 Event 提供事实

事件负责记录：

- 谁做了什么
- 对谁做的
- 发生在什么时候
- 影响了哪些对象
- 影响前后字段是什么

### 11.2 Projection 负责解释

投影负责把事实翻译成：

- 当前主矛盾
- 风险提示
- 下一步建议
- 昨日情报
- 复盘结论

### 11.3 Content 模板负责表达

文案模板负责把解释写成业务话。

但模板不能自己编事实。

如果缺事实，就要降级表达：

```text
目前还缺少足够带看反馈，暂时不能判断 A 房是不是价格卡住。建议先补 2-3 组真实看房反馈。
```

不要硬写：

```text
A 房价格策略需要优化。
```

## 12. 最后一句

去 AI 味不是把句子写得更口语。

而是让每一句话都站在真实业务现场里：

> 有人、有房、有时间、有动作、有证据、有影响、有下一步。

只要守住这一点，文案自然会像业务，不像机器总结。
