# 卖房（资产顾问）设计系统

最后更新：2026-04-21

这份文档收这次首页与市场页重构后，已经在代码里稳定下来的设计系统资产。

目标不是做一个“UI 组件清单”。

目标是让后续页面继续沿着同一套业务桌面语法扩展，而不是回到“大卡片平铺 + 杂色强调”的旧路。

---

## 1. 视觉基调

卖房模块统一采用：

- 深底经营桌面
- 黑绿为主，不混入白页
- 高密度、小字号、多层级
- 重点靠反差、秩序、密度，不靠花哨装饰

不采用：

- 白一块黑一块的混搭
- 多种强调色同时抢主语
- 页面内出现多个 hero 区
- 为了“有设计感”继续增加渐变块和大卡片

---

## 2. Tokens

### 2.1 颜色

基础色：

- `--seller-bg`
- `--seller-bg-strong`
- `--seller-paper`
- `--seller-paper-soft`
- `--seller-panel-alt`
- `--seller-border`
- `--seller-border-strong`
- `--seller-ink`
- `--seller-muted`
- `--seller-subtle`

状态色：

- `--seller-accent`
- `--seller-accent-soft`
- `--seller-risk`
- `--seller-risk-soft`
- `--seller-chance`
- `--seller-chance-soft`

使用规则：

- 信号绿只给今天、当前主判断、激活态、主操作
- 风险红只给确定的风险，不拿来做页面点缀
- 机会蓝只给顺风或推进信号
- 中性色占页面面积 80% 以上

### 2.2 字体

- 正文：`Noto Sans SC`
- 标题 display：`Fraunces`
- 数字 / 技术码：`JetBrains Mono`

使用规则：

- display 字体只给页面顶部主句或非常少量的锚点
- 业务正文、列表、模块标题一律用无衬线

### 2.3 字号

- 页面主句：`30-34px`
- 大数字：`24-28px`
- 模块标题：`15-17px`
- 行标题：`12-13px`
- 正文：`11-12px`
- 标签：`10px`

禁止：

- 同屏出现第二个页面主句级大标题
- 正文回到 13px 以上导致页面发胖

### 2.4 圆角与阴影

- 外层主面板：`15-16px`
- 内层事实块 / 列表块：`12px`
- chip / tab：`999px`
- 阴影只保留 `sm / md / lg` 三档

## 3. 页面骨架

### 3.1 通用骨架

```text
顶部状态与导航
页面主句区
页面主工作区
```

### 3.2 首页骨架

```text
顶部主句 + 资源条
日历轨
左：今日事项队列
右：当前主房源 + 外部变化流
```

首页补充规则：

- 首页首屏要交代完今天的经营桌面，不依赖继续下滚。
- 首页优先回答：
  - 今天先处理什么
  - 当前主房源是谁
  - 今天外部有没有变化
  - 昨天遗留是否影响今天
- 首页不负责展开完整市场拆解，也不负责完整单房决策。

首页固定区块建议保持：

```text
顶部深色简报区
横向周节奏 / 日历轨
左：今日事项队列
右：当前主房源 / 外部变化 / 昨日遗留
```

首页局部规则：

- 首屏不再做夸张 hero 区。
- “受影响房源”不单独再开第四主块，优先并入当前主房源或留给市场页展开。
- 左侧事项队列是首页第一主区，优先级高于右侧说明块。
- 右侧当前主房源不是宣传卡，而是当前主判断入口。

### 3.3 市场页骨架

```text
顶部市场判断 + 总量数
变化传导链
左：证据区
右：受影响房源回流区
```

市场页补充规则：

- 市场页负责“讲外因”，不是第二个首页。
- 市场页优先回答：
  - 外部先变了哪一层
  - 变化证据是什么
  - 变化怎么压到房源
  - 哪些房源最先受影响
- 市场页不再承担“今天先处理哪件事”的首页工作台职责。

## 4. 组件规范

### 4.1 面板

- `seller-workbench-dark`
  用于页面顶部主判断区
- `seller-panel`
  用于页面主内容区
- `seller-panel-soft`
  只用于次级内嵌分区，不再继续嵌套更多层

规则：

- 同一屏最多三层面板层级
- 不再增加新的第四种“特别卡”

### 4.2 Chips

- `seller-chip`
- `seller-chip-accent`
- `seller-chip-risk`
- `seller-chip-chance`

规则：

- chip 是状态和筛选，不是装饰标签
- 同一块里 chip 不超过 3 个

### 4.3 Tabs

- `seller-tabbar`
- `seller-tab`
- `seller-tab-active`

规则：

- 只服务视图切换
- 文案短，不写完整句子

### 4.4 事实块

事实块统一回答三件事：

- 这是什么
- 为什么重要
- 要点是什么

不允许写成空泛总结。

### 4.5 列表行

事项行、情报行、受影响房源行都统一按：

```text
状态 / 类型
标题
一句事实
跳转入口
```

首页事项行补充规则：

- 每条事项必须尽量包含：
  - 时段
  - 类型
  - 标题
  - 一句事实说明
  - 进入下一步的入口

首页主房源块补充规则：

- 固定回答：
  - 现在盯的是哪套
  - 为什么盯它
  - 当前卡在哪
  - 打开后会看到什么

市场页证据行补充规则：

- 先给变化事实，再给影响对象，不先下总结。

---

## 5. 页面职责规则

- 首页只负责排今天顺序
- 市场页只负责解释外部变化怎么传到房源
- 房源页只负责决策与执行
- 客户页只负责关系推进

禁止：

- 在市场页再做第二个工作台
- 在首页再做完整市场总览
- 同一组数据在两个页面都做一级表达

补充去重规则：

- 今日优先事项只允许首页做一级表达。
- 外部变化总览首页只做摘要，深入解释放市场页。
- 受影响房源排序默认由市场页承担。
- 单房决策事实链默认由房源页承担，首页只放短版入口。

---

## 6. 文案规则

- 标题用业务入口语言，不用策划词
- 多写事实，少写判断
- 不用“工作面 / 洞察中心 / 智能建议 / 多维看板”这类词
- 每一条重要文案尽量回答：
  - 谁
  - 哪套房 / 哪个商圈 / 哪个客户
  - 发生了什么
  - 影响了什么

首页文案补充规则：

- 首页优先写业务事实，不写品牌口号。
- 首页主句只保留一个，不再在同屏制造第二个大标题锚点。
- “AI 教练 / 智能建议 / 洞察中台 / 多维看板”这类词继续禁用。

---

## 7. 空态 / 加载态 / 错误态

空态：

- 不说系统词
- 直接说明“现在没有什么”
- 顺手给一个去哪里继续看的入口

加载态：

- 只告诉用户正在准备哪类业务内容
- 不做夸张骨架和品牌化动画

错误态：

- 说明哪块没拿到
- 不把整页打断
- 能继续看别的部分

---

## 8. 后续复用要求

后续新增页面或新模块时，先判断：

1. 它属于哪种页面职责
2. 它应该插入哪种页面骨架
3. 它是否能复用现有面板、事实块、列表行、chip、tab
4. 它有没有重复表达已有页面的一类信息

如果不能回答这四个问题，不要先开始画块。
