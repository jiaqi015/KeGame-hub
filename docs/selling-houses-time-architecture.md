# 卖房（资产顾问）时间架构设计

最后更新：2026-04-19

这份文档回答的是：

> 在这个游戏里，时间不只是 day 往前走。年、季度、月、周内分别是什么意思；城市的时间、商圈的时间、个人的时间又分别是什么。

这份文档不回答：

- 某个页面用日历还是时间线
- 某个字段最终放哪张表
- 某个事件具体概率是多少

它只回答：

1. 时间在这个游戏里分几层
2. 每一层时间到底在表达什么
3. 时间怎么进入市场、商圈、个人和日结引擎

---

## 0. 一句话结论

这个游戏里最稳的时间结构不是一个 `day`，而是三层时间一起存在：

1. `城市时间`
2. `商圈时间`
3. `个人时间`

再往下，每一层时间都要能读懂：

- `年`
- `季度`
- `月`
- `周`
- `日`

一句话理解：

- `年` 讲大周期
- `季度` 讲阶段情绪和经营窗口
- `月` 讲压力和节奏切换
- `周` 讲行动编排
- `日` 讲当天发生什么

这个结构的关键不是“更真实”，而是：

> 不同层级的时间，决定不同层级的变化。

---

## 1. 为什么不能只用一个 day

如果系统只有：

- `day = 17`

后面一定会有几个问题：

1. 周末看房高峰和月底价格松动会混成一类东西
2. 城市级市场变化和经纪人本周安排会混成一层
3. 个人的跟进节奏和市场的周期节奏会混在一起
4. 很多事件只能硬编码成“第几天触发”

所以时间必须拆语义。

这里最重要的一条是：

> 时间不是一个数字，而是一组节奏。

---

## 2. 年、季度、月、周、日分别什么意思

## 2.1 年：大盘背景

`年` 在这个游戏里，不是为了做超长模拟，而是为了定义：

- 这一年大盘偏强还是偏弱
- 这座城市这一年的政策和成交基调
- 哪些 segment 是这一年的热点
- 这一年整体客户信心偏高还是偏低

也就是说：

> 年，代表大的环境背景。

它主要影响：

- 城市级市场情绪
- 贷款和政策氛围
- 各类盘源的基础流动性
- 这一年剧本的“底色”

### 典型例子

- 某年整体偏弱
  高总价盘更难推
- 某年刚需更活跃
  主流两房流动性更强

## 2.2 季度：一段经营窗口

`季度` 在这个游戏里更像：

- 一段阶段性情绪
- 一段政策 / 需求 / 成交窗口
- 一段市场主旋律

它不是年那么大，也不是月那么短。

它主要回答：

- 这段时间整体是升温、盘整还是转冷
- 哪个细分市场进入顺风期
- 哪类客户更容易被推动

一句话：

> 季度，代表阶段行情。

它主要影响：

- 宏观市场事件池
- 城市和区域 sentiment
- 某类客户的决策倾向
- 某类房子的好卖程度

## 2.3 月：压力与松动窗口

`月` 在这个游戏里很重要。

因为很多现实经营的压力和松动，都是按月感知的。

例如：

- 月底更容易出现价格松动
- 月内连续没反馈，业主更焦虑
- 一个月没推进，客户关系明显转冷
- 一整月市场都没起色，会影响城市 / 商圈情绪判断

一句话：

> 月，代表经营压力的累积单位。

它主要影响：

- 价格窗口
- 耐心消耗
- 市场阶段判断
- 月度目标压力

## 2.4 周：行动编排单位

`周` 是玩家最直接能感知的经营节奏。

这个层级最适合承载：

- 本周要做哪些事
- 周末适不适合打开放日
- 哪几天适合做重动作
- 哪些事项本周必须收口

一句话：

> 周，代表行动组织。

它主要影响：

- Matter 排程
- 开放日 / 活动安排
- 玩家经营概览
- 重点事项和提醒

## 2.5 日：事实落账单位

`日` 是引擎真正结算的最小主单位。

一天过去，系统才会：

- 记录今天发生了什么
- 推进日结
- 写入事件
- 切换到明天

一句话：

> 日，代表事实结账。

---

## 3. 三层时间：城市、商圈、个人

这部分是最核心的。

因为不是所有时间都在表达同一种节奏。

## 3.1 城市时间

城市时间回答的是：

> 这座城市现在处在什么市场阶段里。

它更偏“大背景”。

### 城市时间主要承载什么

- 年度基调
- 季度情绪
- 月度政策和成交压力
- 节假日和全城流量变化

### 城市时间的典型问题

- 这一季度整体偏强还是偏弱
- 这个月市场是在修复还是继续下压
- 节后回流窗口是不是打开了
- 本月是不是容易出价格松动

### 城市时间主要影响谁

- `MarketState`
- 城市级 / district 级事件
- 客户整体活跃度基线
- 价格模型基线

一句话：

> 城市时间决定大盘空气。

---

## 3.2 商圈时间

商圈时间回答的是：

> 这个商圈最近到底在忙什么、热什么、挤不挤。

它比城市时间更近，更像真实经营现场。

### 商圈时间主要承载什么

- 周末客流节奏
- 商圈活动周
- 竞品集中动作期
- 新盘 / 新挂牌波次
- 某段时间的流量高低

### 商圈时间的典型问题

- 本周末这个商圈是不是更适合开放日
- 这几天竞品是不是在集中抢流量
- 这个月商圈客流是在升还是在掉
- 最近是不是同质房一下变多了

### 商圈时间主要影响谁

- `BizArea` 级市场事件
- `CaseRuntime.exposure`
- `rivalPressure`
- 开放日和推广动作的命中率

一句话：

> 城市时间像天气，商圈时间像街上的人流。

---

## 3.3 个人时间

个人时间回答的是：

> 对这个经纪人、这套房、这个客户来说，现在处在什么节奏里。

它不是市场时间的缩小版。
它是经营对象自己的节奏。

### 个人时间主要承载什么

- 距离上次联系过了几天
- 某个 Matter 还有几天到期
- 某个客户已经停滞几天
- 某个业主已经连续几天没反馈
- 本周个人精力和动作排布

### 个人时间的典型问题

- 这个客户是不是该跟进了
- 这套房是不是快到耐心临界点
- 这个事项是不是该今天收口
- 这周我是不是已经把重动作打满了

### 个人时间主要影响谁

- `Matter`
- `BrokerOwnerRelation`
- `BrokerCustomerRelation`
- `OwnerCaseRelation`
- `CustomerCaseRelation`
- `BrokerRuntimeState`

一句话：

> 个人时间决定今天我先处理谁。

---

## 4. 三层时间之间是什么关系

最稳的理解是：

```text
城市时间
  -> 决定大的市场基调
  -> 影响商圈时间的强弱
  -> 影响个人动作的大环境

商圈时间
  -> 决定这个局部市场这几天的流量和竞争
  -> 影响房源、活动、推广、带看

个人时间
  -> 决定这一局里哪些关系在变热、变冷、快超时
  -> 决定玩家今天的动作顺序
```

也就是说：

- 城市时间，不直接告诉你今天跟谁打电话
- 个人时间，也不决定全城行情

它们层级不同，但会互相传导。

## 5. 时间应该怎么进入引擎

我建议统一做一个：

```ts
type TimeContext = {
  absoluteDay: number;

  calendar: {
    year: number;
    quarter: number;
    month: number;
    weekOfYear: number;
    dayOfMonth: number;
    dayOfWeek: number;
    isWeekend: boolean;
    isMonthStart: boolean;
    isMonthEnd: boolean;
    isQuarterStart: boolean;
    isQuarterEnd: boolean;
  };

  cityPhase: {
    annualTheme?: string;
    quarterSentiment?: 'up' | 'flat' | 'down';
    monthlyPressure?: number;
  };
};
```

然后在不同层再补：

```ts
type BizAreaTimeState = {
  bizAreaId: string;
  weeklyTrafficPhase: 'low' | 'normal' | 'peak';
  currentCampaignWeek?: boolean;
  rivalActionDensity: number;
  recentListingWave: number;
};

type PersonalTimeState = {
  actorId: string;
  daysSinceLastOwnerContact?: number;
  daysSinceLastCustomerContact?: number;
  daysSinceLastShowing?: number;
  stagnationDays?: number;
  matterDeadlineInDays?: number;
  weeklyLoad?: number;
};
```

这里最重要的不是字段多少，而是：

> 城市、商圈、个人不要共用一套时间状态。

## 6. 年、季度、月、周、日分别进入哪里

这张表最关键。

| 时间层级 | 最适合进入哪里 | 主要影响什么 |
| ---- | ---- | ---- |
| 年 | 城市基线 / 剧本背景 | 大盘基调、政策气候、细分市场底色 |
| 季度 | MarketState / 宏观事件池 | 情绪切换、需求强弱、城市级窗口 |
| 月 | 价格压力、业主耐心、目标压力 | 松价窗口、月度累积压力、月内表现判断 |
| 周 | 经营概览、活动安排、事项编排 | 开放日、重点事项、本周动作排序 |
| 日 | 日结引擎、事件落账 | 今日事实、关系变化、状态推进 |

---

## 7. 时间对城市、商圈、个人分别意味着什么

## 7.1 对城市来说

- `年`
  是这一年大盘的底色
- `季度`
  是阶段情绪和窗口
- `月`
  是政策 / 成交 / 压力观察单位
- `周`
  只是局部节奏，不是主层
- `日`
  是事件真正落账的时间点

## 7.2 对商圈来说

- `年`
  只决定长期环境，不是主要感知层
- `季度`
  影响这个商圈一段时间的热冷
- `月`
  体现这个商圈最近竞争和供给变化
- `周`
  是最关键层，决定客流、活动、开放日
- `日`
  决定今天有没有客流、活动、竞品动作

## 7.3 对个人来说

- `年`
  只是背景
- `季度`
  决定这段时间打起来顺不顺
- `月`
  决定目标压力、耐心变化、关系消耗
- `周`
  是个人经营主视角
- `日`
  是跟进、带看、沟通、推进的结账单位

也就是说：

> 对玩家最有感的主时间层，是“周 + 日”；对市场最有感的主时间层，是“季度 + 月”；对商圈最有感的主时间层，是“周”。

## 8. 页面上该怎么投影时间

这个游戏里，时间不应该只显示成日期。

应该投影成节奏。

### 经营概览

最适合投影：

- 一周节奏
- 今日 / 昨日新闻
- 本周重点事项
- 周末窗口

### 市场雷达

最适合投影：

- 本月市场阶段
- 本季度情绪
- 本周商圈动静
- 未来几天的重要窗口

### 房源详情 / 客户详情

最适合投影：

- 上次联系距今天数
- 当前停滞天数
- 下次关键节点
- 最近一段时间线

一句话：

> 页面不要只是显示“4 月 19 日”，而要显示“现在正处在什么节奏里”。

---

## 9. 设计原则

## 9.1 时间不是字段，是语义

不要把时间理解成：

- `createdAt`
- `updatedAt`
- `day`

这太浅了。

在这个项目里，时间真正有价值的是：

- 窗口
- 节奏
- 压力
- 周期

## 9.2 不同层的时间不要互相代替

不能用“个人最近 7 天没动作”去代替“商圈本周转冷”。

也不能用“这个月市场偏弱”去代替“这个客户已经停滞 12 天”。

## 9.3 时间先改环境，再改关系，再改投影

最稳的传导链是：

```text
时间结构
  -> 市场 / 商圈事件
  -> 房源 / 客户 / 业主 / 关系
  -> Matter 和动作窗口
  -> 页面提醒和摘要
```

不要跳级。

## 9.4 让时间可解释

以后任何自动变化，最好都能回答：

- 是因为周末窗口吗
- 是因为月底松动吗
- 是因为这个客户已经停滞太久吗
- 是因为本商圈最近竞争抬升吗

如果回答不了，说明时间还没真正进模型。

---

## 10. 最后一句

这个游戏里的时间，不能只做成“第几天”。

它应该同时告诉系统三件事：

1. 这座城市现在处在什么阶段
2. 这个商圈最近在发生什么节奏
3. 这个人和这些关系现在该不该动、该先动谁

只有这样，时间才不是背景板，而是真正推动世界变化的骨架。
