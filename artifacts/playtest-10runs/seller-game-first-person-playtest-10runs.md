## 1. 总体结论

这 10 局都能从 `/seller?profile=e2e` 开局、推进天数、执行动作、日结并进入最终结算；从“能玩通”角度，关键链路成立。更准确地说：它现在是一个**有卖房经营素材和日历框架的可玩原型**，但还不是一个稳定成立的“日历驱动卖房经营模拟”。

最硬的证据是：10 局不同人格全部在 DAY 15 触发结算，全部得到同一类结果：`STANDARD 没保住`、`9/72`、`本局成交 0 套`、`5 套结果较差`。这不是单纯“玩家打得差”，而是说明当前前台策略空间太窄：不同人格最后都被页面可见行动 funnel 到早期反复做“首次面访”，DAY 9 之后又频繁出现“找不到可执行动作 / 只能推进日历”的状态。

核心判断：

- **是否真的能玩**：能玩通 10 局，但后半局经常从经营变成等待结算。
- **是否像经营游戏**：像经营游戏的骨架，有天数、精力、房源、业主、客户、竞品、市场、日结；但动作后果和状态 diff 缺少可追踪因果。
- **是否像卖房业务**：素材像，尤其是业主焦虑、客户预算卡点、竞品比较、挂牌价/市场价/底线；但情报没有稳定转成经纪人动作。
- **是否有每日期待**：D1-D8 有期待，D9-D15 明显下降；很多天像“看系统播报”而不是“我在经营”。
- **是否知道为什么赢/输**：最终知道自己输了，但不知道每个失败如何由每日动作累计而来。
- **最大问题类型**：第一是反馈因果问题，第二是信息架构问题，第三是模拟深度/策略分化问题；功能阻断不是主问题。

一句话结论：当前玩家更像在“读一组卖房业务播报并点几个动作”，还没有稳定感到“我真的在经营一套正在出售的房子”。

## 4. 玩家心智变化分析

- DAY 1：我以为这是“看消息 → 选房源 → 做动作 → 日结”的经营模拟。
- DAY 3：我开始理解核心对象是业主信任、客户推进、价格差、竞品压力，但还不能稳定判断动作优先级。
- DAY 7：我形成粗策略：先做面访和反馈，再看客户/价格。但这更像按钮顺序学习。
- DAY 14：局势会继续变化，但事件缺少统一 ledger，玩家很难回忆“为什么变成这样”。
- 最后：我知道大概输赢来自成交/信任/客户推进，但不知道具体每次选择如何累计成结果。
- 10 局之后：能总结出有效打法轮廓，但重玩价值受限，因为因果反馈不够透明。

## 5. 经营感诊断

### 5.1 时间经营感

- 每天有日历和消息，但有些天像“换一批播报”。
- 日历推进有意义，特别是周末带看、业主反馈、内部会议这些节点。
- 推进一天的体验比推进一周更可理解；推进一周会放大因果断裂。
- 空转天主要来自玩家没找到可行动作或行动反馈不闭环。
- 关键节点存在，但没有被组织成“事件链”。

### 5.2 房源经营感

- 能感觉房源在市场里竞争：挂牌、市场位、底线、同类房压力都可见。
- 房源热度变化不够可解释，缺少“因为推广/带看/竞品，热度变化”。
- 卖点、价格、客户反馈尚未形成强闭环。
- 房源更像状态卡片，不够像正在被经营的资产。

### 5.3 业主经营感

- 业主有情绪标签和消息，比较像人。
- 沟通会影响信任/耐心，但解释不足。
- 业主是否根据市场反馈改变想法，玩家感知弱。
- 目前业主像“有人设的状态条”，还没完全像真实业主。

### 5.4 客户经营感

- 客户有预算、意向、剩余时间等信号。
- 反馈可用但不够具体，缺少为什么喜欢/不喜欢。
- 带看差异需要更明确的反馈字段。
- 客户行为能提供策略依据，但入口分散。

### 5.5 市场竞争感

- 竞品/同类房压力可见。
- 市场会变，但变化与我的动作关系弱。
- 竞品影响我，但缺少“客户重合/价格对比/流失原因”的强证据。
- 价格策略有潜力，是最接近真实业务的部分。

## 8. 情报站专项诊断

- 像经纪人的微信，但更像消息列表，不够像情报站。
- 优先级有“紧急/今日重点”，但所有紧急放在一起时仍拥挤。
- 信息意义需要玩家自己翻译。
- 情报没有稳定转成行动。
- 没有让我强烈感觉“我掌握了别人不知道的信息”。
- 类型边界不够清：市场、客户、业主、竞品、组织消息混在一起。

## 10. P0 / P1 / P2 问题分级

### P0-00：本次未发现开局/推进/结算阻断级 P0

发生位置：全链路
复现路径：10 局从 `/seller?profile=e2e` 新开局到结算
玩家当时看到：均可进入标准剧本、推进日期并完成结算
玩家当时怎么理解：游戏可以跑通，但体验问题集中在经营感和因果感
实际问题：无关键路径阻断，但存在多项 P1 核心体验问题
影响：不阻断试玩，但影响是否愿意重玩
建议改法：优先修 P1 因果链、情报行动化、后半局空转
建议测试：保留新开局、日推进、结算、刷新恢复 e2e 冒烟

### P1-01：不同人格无法打出明显不同策略

发生位置：工作台、我的房源、行动区、结算
复现路径：10 局分别按新手/激进/保守/价格/客户/熟练等人格玩
玩家当时看到：可见动作长期集中在“首次面访”，后半段经常没有可执行动作
玩家当时怎么理解：我换了玩法心态，但系统没有给我足够不同的抓手
实际问题：策略空间被行动入口和信息架构压扁
影响：重玩价值弱，熟练玩家也像在熟悉按钮顺序
建议改法：按人格/策略提供不同可行路径，例如“客户冲刺、业主稳价、竞品反击、价格谈判”都要有对应动作链
建议测试：同一 seed 下三种策略至少产生不同 action mix、状态 diff 和结算解释

### P1-02：行动结果缺少可追踪因果链

发生位置：行动弹层、状态变化、日结
复现路径：进入任意一天 → 我的房源 → 执行动作 → 看反馈/日结
玩家当时看到：状态变化、信任 +N、耐心 +N、日结播报
玩家当时怎么理解：我知道系统给了结果，但不知道为什么
实际问题：行动、选项、对象反应、指标变化之间没有统一 eventId/causedBy
影响：经营感被削弱，像抽卡播报
建议改法：每次行动后输出“选择 → 对象反应 → 指标变化 → 后续风险/机会”
建议测试：断言行动后出现 causedBy 文案和至少一个对象级 diff

### P1-03：情报站不能稳定转成行动

发生位置：我的微信 / 今日关注 / 经理消息 / 客户消息
复现路径：工作台读取消息 → 尝试去房源页或客户页行动
玩家当时看到：业主、客户、经理、商圈经理消息混排
玩家当时怎么理解：消息重要，但不知道该点哪个动作
实际问题：消息缺少建议动作、不处理风险和关联对象
影响：情报站像消息堆，不像经营雷达
建议改法：消息卡增加“影响对象 / 建议动作 / 不处理风险 / 追踪结果”
建议测试：每条紧急消息至少关联一个 listingId/customerId/actionId

### P1-04：DAY 9 之后明显空转

发生位置：工作台、行动区、日结
复现路径：多数 run 推进到 DAY 9-D15
玩家当时看到：仍有消息/市场变化，但行动区常返回“没有找到可执行动作”
玩家当时怎么理解：世界还在播，但我手里没活可干
实际问题：后半局事件和玩家动作脱钩
影响：日历驱动变弱，玩家只是在等最终失败
建议改法：后半局增加“补救动作”：降价沟通、客户召回、竞品反击、业主止损、二次带看、最终谈判
建议测试：DAY 9-D15 每天至少存在 1 个与当前风险相关的可执行动作或明确空态解释

### P1-05：最终结算有失败叙事，但缺少每日归因

发生位置：本局正式结算
复现路径：任意 run 到 DAY 15
玩家当时看到：0 成交、5 套结果较差、对手成交 2 套、部分房源核销/他处成交
玩家当时怎么理解：我输了，但不知道是哪几天没做好导致输
实际问题：结算展示结果多，缺少关键路径回放
影响：玩家不能学习，下一局只能凭感觉重试
建议改法：结算页增加“败因链”：DAY X 未处理业主耐心 → DAY Y 客户流失 → DAY Z 竞品成交
建议测试：结算页至少列 3 条 causedBy 链路，且能回跳到当天事件

### P2-01：行动按钮文案偏机制标签

发生位置：我的房源行动区
复现路径：查看“首次面访 / 面访反馈 / 营销推广 / 价格沟通”等动作
玩家当时看到：动作名 + 简短状态 + 精力
玩家当时怎么理解：知道要花精力，但不知道适用条件和风险
实际问题：业务语境不足
影响：选择靠猜
建议改法：动作按钮下加“适合现在因为… / 可能带来… / 不适合时…”
建议测试：关键动作都展示 cost、expectedImpact、risk

### P2-02：每日页面文本过长，玩家难以抓重点

发生位置：工作台、日历、今日安排、微信
复现路径：任意 DAY 开始观察
玩家当时看到：日历、安排、候选、消息、按钮大量并列
玩家当时怎么理解：信息很多，但第一眼不知道今天最该管谁
实际问题：结构没有把“必须处理”和“可观察”拉开
影响：新手上手成本高
建议改法：首屏只保留今日必须处理、最高风险对象、一个主行动入口；其它折叠
建议测试：D1 首屏无需滚动可读出今日主对象、主风险、主动作

### P2-03：文案有真实业务素材，但经常缺判断字段

发生位置：微信、市场新闻、客户反馈、业主反馈
复现路径：阅读消息后做决策
玩家当时看到：客户预算卡、业主不耐烦、竞品装修新等内容
玩家当时怎么理解：这像真业务，但还要自己翻译成动作
实际问题：缺“这意味着什么”
影响：情报不能沉淀成策略
建议改法：每条业务文案增加一句短判断，如“影响：客户可能转向装修更新的竞品”
建议测试：紧急消息必须有 impactSummary 字段

## 12. 疑似 bug 与修复建议

### BUG-01：每个新浏览器上下文都会先出现一次 401 资源错误

问题现象：`console-and-page-errors.json` 中 10 局各记录 1 条 `Failed to load resource: the server responded with a status of 401 (Unauthorized)`。
复现路径：新浏览器上下文打开 `/seller?profile=e2e`，登录前触发鉴权请求。
发生频率：10/10。
影响范围：目前不阻断登录和试玩，但会污染 e2e console error 基线。
疑似原因：页面初载先请求受保护资源，再进入登录/恢复流程。
建议修复：对预期未登录请求降级为 handled state，或在 e2e 中等待登录后再断言 console 清洁。
建议补充测试：`seller e2e auth bootstrap should not emit unexpected pageerror`，允许白名单 401 或消除该请求。

### BUG-02：行动弹层“进入下一轮”渲染/点击时机不稳定，容易阻塞后续日结

问题现象：探针阶段多次看到行动反馈弹层遮住“结束今日”；必须等待按钮出现并用坐标点击才能稳定收尾。
复现路径：我的房源 → 首次面访 → 选择第一轮话术 → 确认 → 等待“进入下一轮”。
发生频率：自动化探针中高频；最终 runner 通过真实鼠标坐标点击规避。
影响范围：玩家肉眼可点，但自动化和弱网/慢渲染下容易误判动作未完成，影响 e2e 稳定性。
疑似原因：状态反馈先渲染，下一轮按钮稍后出现；弹层没有明确 final/step state contract。
建议修复：弹层状态机拆成 `choosing | feedback | nextReady | completed`，按钮和状态同步渲染；加 data-testid。
建议补充测试：多轮行动执行后必须进入第二轮，最终关闭弹层并恢复“结束今日”可点击。

### BUG-03：结算文本里“成交概况 0 成交”和“对手成交”容易被简单匹配误判

问题现象：原始 run-summary 自动判断曾把“成交概况 0 成交 / 对手成交 2 套”误识别成“是否成交：是”。主报告已人工修正为“本局成交 0 套”。
复现路径：读取结算页全文，用宽松正则判断是否成交。
发生频率：10/10 原始摘要均有风险。
影响范围：测试与数据分析容易把对手成交/页面导航文案误当我方成交。
疑似原因：结算缺少结构化字段或自动化没有读取明确 winner 字段。
建议修复：结算页暴露结构化 `ownSoldCount` / `rivalSoldCount` / `listingOutcomes`，并给 UI 加 testid。
建议补充测试：断言“本局成交 0 套”时 summary result 必须是未成交。
